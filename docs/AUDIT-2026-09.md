# PhotonScript — Code & Feature Audit (2026-09-25)

Scope: ~14.5k LOC Python. Mission lens: *maximize shutter time, turn it into
award-winning images.* Ranked by ROI toward that mission (stop wasting nights
first, then throughput/quality, then the tech debt that unblocks the rest).

---

## The 5 next major moves (if you do nothing else)

**1. Close the autofocus loop — validate it, and revive the temperature model.**
This is the #1 recurring night-killer (the 2026-09-24 donut night). Two linked
fixes:
- **Validate AF at the source.** `_autofocus()` runs with `Attempts=2` but
  PhotonScript never parses the result — no final-HFR/R² check, no gate, no
  alert. A soft/failed AF degrades every following sub until the *passive* QA
  gates reject them after the fact. Add a post-AF HFR sanity check (reject/retry
  if final HFR > threshold or the run didn't converge) + a Pushover.
- **Revive focus seeds (dead code).** `focus_seeds.harvest_night()` is defined
  but called from nowhere, and `nina_sequence_json._seed_position()` always
  passes `ambient_c=None`, so the temperature linear-fit branch never runs — RC16
  seeds never self-improve or temp-compensate (the piggyback does). Wire harvest
  into the nightly backfill and thread focuser temperature in.
*Impact: prevents the exact soft-focus/donut nights. Effort: medium.*

**2. Cross-night data-quality trend analysis + polar-drift alarm.**
Grading is strictly per-frame, so the *month* of trailed subs (2026-07-28 →
09-04) went uncaught. A trend detector on median FWHM / eccentricity / ecc-PA /
background per target+filter across nights — plus a uniform-PA polar-drift alert
from the shape signal already computed — catches a systematic rig fault in **one
night instead of a month**. Single biggest shutter-time saver.
*Effort: medium; reuses existing per-frame diagnostics.*

**3. Meridian-flip robustness.**
Targets are transit-ordered only. A target sitting at the meridian at dark-start
still triggers the immediate-flip + recenter-failure that burned 4+ hours on
2026-07-07 (still a HANDBOOK backlog item). Defer a just-past-meridian target or
split it around the flip.
*Effort: small–medium; well-scoped in the planner.*

**4. Test the arm state machine + add a CI/deploy gate.**
`armer.py` (the code that decides whether the rig images, pauses, shuts down) is
effectively untested — one persistence test. And `deploy/deploy.ps1` runs **no
pytest/ruff/mypy** before pushing to the scope. A regression fails at 3 a.m.
against live hardware with nothing to catch it. Add `test_armer.py` (the repo's
`FakeNina` watchdog tests are a good template) covering the transitions +
`dawn_shutdown`, and gate deploy on `pytest && ruff && mypy`.
*Effort: medium; pure insurance, high leverage.*

**5. Surface silent failures instead of swallowing them.**
136 `noqa: BLE001` swallow-sites; the dangerous ones hide *imaging* failures:
- `telescope_agent/agent.py:709` — a graded sub's QA write to `_subs.jsonl`
  fails → logged at **DEBUG** only → the sub silently never enters the runs
  page/library/transfer funnel.
- `telescope_agent/agent.py:249` — the safety-monitor watchdog returns **mute**
  (no log) when NINA is unreachable, exactly when "image a closed roof" is the
  risk it exists to prevent.
Promote imaging-critical failures to a dashboard health flag + alert; count
watchdog-blind cycles toward the existing escalation.
*Effort: small, targeted.*

## Reliability / observability (harden the automation)

- **Guiding watchdog is untested and warn-only.** `_maybe_warn_not_guiding`
  (added this session) is the sole guard against "armed guided but PHD2 idle."
  It fires once, only warns (never pauses), and swallows NINA errors. Add a test,
  and consider a pause/re-arm action, not just a Pushover.
- **Dawn-shutdown / cooler-off verify is safety-critical and untested.**
  `_verify_shutdown` exists because 2026-09-15 left both coolers at 0 °C all day;
  it runs once + one retry then only Pushovers. If that async task is cancelled
  (restart/disarm) a stuck cooler goes unnoticed. Needs coverage.
- **Transfer/backlog has no failure detection.** The ~45k-file Syncthing backlog
  is only *reported*; the librarian's SSH transfer loop silently re-queues on
  exception forever (`agent.py:229`). Add a stalled/growing-backlog alarm.
- **OSC (NINA #2) observability.** No remote NINA-#2 log tail (only NINA #1);
  companion dispatch is fire-and-forget. Add an `/api/nina/log?rig=piggyback`
  and verify the OSC library-routing path (below).

## Features toward the mission

- **Integration/stacking automation.** PixInsight/OSC pipelines are manual
  desktop PowerShell. A "target complete → auto-stage → integrate → preview JPG"
  trigger closes the photons→master loop.
- **Piggyback slew-gating (DUAL_RIG Phase 4) + verify OSC calibration routing.**
  ~half of OSC subs on a two-pointing night are only salvaged by post-hoc culling
  — live-pause NINA #2 during RC16 slews to reclaim them. And verify OSC lights
  land where calibration matching scans (`Library/_/OSC` vs `Library/piggyback`)
  — if not, **every OSC master is uncalibrated**. Low-effort, high-value check.
- **Campaign completion tracking.** Campaign v1 is capacity-only (ETAs are
  estimates; visibility windows not folded in). Add per-target "nights-to-finish
  given visibility × moon × forecast" + completion notifications.
- **Pixel-scale-aware dithering + mid-night adaptive BB↔NB swap** using the
  all-sky/forecast signals already fetched.

## Structural / tech debt (unblocks the above)

- **Fix the `/api/runs/{date}` hang.** `night_detail` re-scans the whole night's
  FITS synchronously on every request (`build_daily_report` + `calibration_inventory`,
  two full `rglob`+header reads), on the request thread, contending for the
  `_HEAVY` lock with the backfill grader. It's biting contact sheets + review.
  Cache per night, read the graded `_subs.jsonl` (never open FITS inline), and
  default `backfill=False`.
- **`app.py` is 2274 lines / 84 routes + in-memory state.** Split into routers
  (runs, calibration, rigs, sync, system); move state/service logic out of the
  web layer. Unblocks testing.
- **Config sprawl: 113 flat env fields** in one `PhotonScriptConfig`. Group
  (observatory / imaging-quality / calibration / rigs / sync) and move tuning
  *constants* out of deployment settings.
- **Extract shared NINA-JSON builders.** `generate_nina_json` (283-line hand-
  rolled builder) and `generate_piggyback_companion_json` duplicate container/
  trigger construction with literal `NINA.Sequencer.*` type strings — brittle vs
  NINA schema changes, untestable as one unit.
- **Guard global mutable job state.** `_backfill_state` / `_regrade_all` module
  dicts are mutated from daemon threads and read by request handlers without
  locks; `start_regrade_all` busy-waits. Add a lock / small job-manager.
- **Housekeeping:** promote the dated inline-comment fragilities
  (`armer.py:13/327` WaitUntilSafe wedge, `nina_sequence_json.py:340` empty-
  container crash, `preflight.py:154` safety monitor "bit us") to tracked issues;
  `.pyc` files are committed — add to `.gitignore`.

### Suggested sequencing
1. AF validate + focus-seed revival, polar-drift/trend alarm, meridian handling
   → stops the known night-killers.
2. `test_armer.py` + deploy gate (pytest/ruff/mypy) + surface silent failures
   → makes every future change safe.
3. Fix the runs-detail hang; then the app.py/router + config refactor
   → unblocks testing and the feature work.
4. Integration automation, piggyback slew-gating, campaign completion tracking
   → throughput + quality.

*Health snapshot: 0 CI, 0 lint/type gate before deploy; 37 test files but the
biggest side-effect-heavy modules (armer, runs, the agent image path) are the
least covered. Test **quality** is good (real fakes, no wall-clock flakiness) —
the gap is breadth + the missing deploy gate.*
