# PhotonScript — Dual-Rig Plan (RC16 + 600 mm piggyback)

**Status: LIVING PLAN — pre-build, nothing deployed.**
Owner: Jeremy · Last updated: 2026-09-12
Sequence: flesh out → **red-team** → modify → build in phases.

---

## 1. Goal

Image with the 600 mm piggyback (OGMA AP26CC, one-shot color) **at the same
time** as the RC16 main rig, on the same pointing — free extra data every clear
night. Each session yields a **tight deep crop** from the RC16 (0.24"/px) *and*
a **wide-field OSC frame** (~1.3"/px) of the surrounding region, from the same
shutter time and the same mount.

They are not identical frames — same pointing, different scale and framing. The
piggyback is the environmental wide-field companion to the RC16's close-up.

---

## 2. Locked decisions

- **No coordination code.** The piggyback images whenever the mount is generally
  tracking. Subs caught during slews / plate-solve centering / meridian flip are
  expected to trail and get rejected by QA. We accept the small loss (the RC16
  dwells for hours and slews rarely). Revisit only if the loss rate annoys.
- **Guiding is committed to the OAG (GP678C) on the RC16.** The AP26CC is
  released from guide duty and becomes the piggyback imager.
- **The piggyback is not independently pointable** — it rides the RC16's
  pointing at a fixed offset and frames the wide field around the main target.
- **No RAM pre-optimization.** Try it, watch load via a new stats endpoint,
  adjust.
- PhotonScript must learn to **see both rigs**, with settings and controls for
  each; the librarian and file moves must track **which rig** each file is from.
- **Piggyback Pushover is silent** (or at most one nightly one-line summary) — the
  loop has nothing to narrate and must not re-flood the channel.
- **The piggyback keeps its own darks/flats/bias (DAR).** OSC calibration is
  wholly separate from the RC16's; per-rig calibration is required, not optional.

## 4. Capture architecture

### 4.1 Two NINA instances
- **NINA #1 "RC16"** (existing): owns mount + PHD2(OAG) + AP26MC + filter wheel +
  main focuser. Runs the existing PhotonScript night sequence unchanged.
  Advanced API `:1888`.
- **NINA #2 "Piggy-600"** (new): owns **only** AP26CC + piggyback focuser.
  Advanced API on a **new port (proposed `:1889`)**. Connects the same Alpaca
  safety monitor (read). **Does not own the mount.**
- Devices are on distinct ports, so the instances don't contend for handles. The
  only shared hardware is the mount (Rig A only) and the safety monitor (read
  from both).

### 4.2 Target/coordinate metadata for the piggyback
The piggyback needs a target name for QA + library, but can't command the mount.
Two options:
- **(Preferred) Time-correlation.** PhotonScript already knows what Rig A was
  pointed at over time. Tag each piggyback sub's target by matching its capture
  time to Rig A's target timeline. No mount contention at all.
- **(Optional) Read-only mount** via ASCOM Device Hub so NINA #2 stamps RA/DEC
  into the FITS; then the **identify-by-coords + OBJECT-stamp we already shipped
  tags piggyback frames automatically**. Needs TheSky/DeviceHub to allow a
  second read client (verify).

Recommendation: start with time-correlation; add read-only coords if useful.

### 4.3 Piggyback sequence (a simple, dumb loop)
A minimal OSC night loop generated by PhotonScript:
- connect AP26CC + focuser + safety; cool to setpoint;
- `WaitUntilSafe`; loop until dawn: ensure focused (AF once per session + a
  temperature trigger), then take OSC exposures continuously;
- `SafetyMonitorCondition` parks the loop when unsafe.
- **No** slew / center / filter / guiding / dither instructions — those belong to
  Rig A; the piggyback just rides.
- **Exposure: default 120 s OSC (range 60–180 s)** — see §4.5.

### 4.4 Framing, dithers, flips (stacking implications)
- Fixed offset → set AP26CC **rotation once** so the wide field frames well around
  common targets.
- Rig A dithers move the mount → the piggyback is dithered too (normal for
  registration).
- **Meridian flip:** the field rotates 180° between pre/post-flip piggyback subs
  (registration handles it); subs exposing *during* the flip trail and are
  rejected.

### 4.5 Exposure — why ~120 s regardless of the exact f-ratio

Camera confirmed: OGMA AP26CC = Sony **IMX571 APS-C color**, 6224×4168, 3.76 µm,
read noise **0.8–1.3 e⁻ (HCG)** / 1.5–3.2 e⁻ (LCG), full well **100 ke⁻**, 16-bit,
gain 1–100×, QE peak >80%.

The piggyback is *massively* sky-rich per pixel: at 1.29"/px it collects
(1.29/0.239)² ≈ **29× more sky per pixel** than the RC16. The RC16 is already
background-limited at 180 s broadband (f/8, 0.24"/px, SQM 23.9). Scaling that to
the piggyback: sky-limited time ≈ 180 × (f_piggy/8)² × (0.239/1.29)² ≈
**6 × (f_piggy/8)²** seconds. Even at f/8 that's ~6 s — i.e. the piggyback reaches
background-limited in **seconds at any realistic f-ratio** for a 600 mm.

So exposure is **not** set by swamping read noise (that's trivially met). It's set
by the other end — **not saturating too many stars** (100 ke⁻ fills fast on rich
Milky Way fields at HCG) and keeping file counts / dither cadence sane. Practical
call: **120 s OSC default**, drop to 60–90 s on dense/bright fields, up to 180 s on
faint high-latitude targets. Gain at HCG/unity. This is why we don't need the exact
aperture to start — the daytime bring-up (§6.0) will confirm f-ratio, but it won't
move the exposure much.

## 5. PhotonScript changes — the "rig" dimension

Everything below is currently single-rig; the core work is threading a `rig` id
through the pipeline.

### 5.1 Config
- **Phase-0 minimal:** a second config/env profile (e.g. `--rig piggy600` or a
  `PS2_` prefix) driving a second telescope-agent process with piggyback values:
  `image_watch_dir`, `nina_base_url` (`:1889`), `pixel_scale_arcsec=1.29`,
  `quality_hfr_abs_max≈4.5` (the 8 px gate is meaningless at 1.29"/px — a focused
  star is ~2 px), filter map = `OSC`, camera setpoint, dark exposures, library
  subtree.
- **Mature form:** a first-class `rigs: [ {id, name, …} ]` list the scheduler
  reads so one process can serve both.

### 5.2 telescope_agent
- Phase 0: run a **second instance** with the piggyback config (reuses all
  grading logic verbatim).
- Tag every sub record with `rig` (`"rc16"` / `"piggy600"`).
- Per-rig pixel scale + QA thresholds.
- OSC: no filter → record `filter="OSC"`; star detection on luminance/green of
  the debayered frame.

### 5.3 runs / QA / scoring
- Add `rig` to sub records and `_load_subs`; runs page gains a **rig toggle /
  column**; night score computed **per rig** (combined view optional).
- `identify`: per-rig plate scale for ASTAP; OSC solves fine.

### 5.4 Librarian + file moves *(the part to get right)*
- Library layout gains a rig level: **`Library/<Rig>/<Target>/<Filter-or-OSC>/`**
  — keeps RC16 LRGB/SHO separate from piggyback OSC, no name collisions.
- Thread `rig` through `build_library`, `approve_night`, `stage_for_analysis`,
  `sync_goal_progress` so each routes to the right subtree.
- Syncthing mirrors each per-rig subtree; verify the desktop mirror carries both
  without collision.
- Transfer/backlog counts reported per rig.

### 5.5 Calibration (per rig)
- Separate **dark / flat / bias** libraries per camera. OSC needs its **own
  flats** (its optics/vignetting) and darks (its exposures). The dark-quota and
  dawn-flats logic becomes per rig, at the AP26CC's gain/offset/temp.

### 5.6 Image processor
- Group by `rig`+target+filter. OSC path = **debayer → register → stack** (vs
  mono per-filter). Add an OSC Siril/PI branch.

### 5.7 System stats endpoint — **BUILT 2026-09-12**
- `GET /api/system/stats` (psutil): RAM used/total/available, CPU %, the heavy
  astro processes (NINA / PHD2 / TheSky / python / astap / PixInsight / siril)
  with per-process RAM, and disk free on the image + library volumes. Surfaced on
  the System page ("Host Load" card). `psutil` added to `pyproject`. Best-effort:
  returns `available:false` if psutil isn't installed. **This is the instrument
  for the daytime bring-up test (§6.0).** Not deployed until `deploy.ps1`.

### 5.8 UI
- Dashboard + runs + system show **both rigs** with controls for each (arm/disarm
  the piggyback loop, its state, its subs, its library, its calibration).

## 6. Phased rollout

### 6.0 Daytime two-camera bring-up (gating test — do this FIRST)

The whole plan hinges on the OGMA driver tolerating two IMX571 cameras at once.
Falsify that cheaply in daylight before writing any capture code (roof closed,
caps ON — this is an electronics/USB test, not an imaging test):

1. **Deploy first** so the scope PC has `/api/system/stats` (`.\deploy\deploy.ps1
   "system stats endpoint"`, then `pip install -e .` picks up psutil), and open
   the System page → Host Load. Note the idle baseline (RAM/CPU, and which
   processes are already resident).
2. **USB topology** — in Windows Device Manager (View → Devices by connection, or
   USBView) note whether AP26MC and AP26CC land on the **same USB3 controller/hub**
   or different ones. Same hub + two 26 MP streams is the bandwidth risk.
3. **Instance #1** (existing "RC16" NINA): connect AP26MC as usual. Confirm still
   healthy.
4. **Instance #2**: launch a second NINA (`--profile` or a copied profile
   "Piggy-600"), set its Advanced API port to **1889**, connect **only** the
   AP26CC + the piggyback focuser. → *Does the second camera connect while the
   first is live?* This is the make-or-break moment.
5. **Simultaneous capture** — take continuous exposures on **both** at once (a few
   min of 2–5 s frames is plenty; caps on, it's about the data path not the light):
   watch for download failures, USB timeouts, driver disconnects, or one camera
   knocking the other offline. Refresh Host Load and record peak RAM/CPU with both
   running.
6. **PHD2 check** — confirm PHD2 selects **GP678C (OAG)** and never the AP26CC, so
   guiding and the piggyback imager don't fight over the camera.
7. **Focus** — slew the focuser on the piggyback a few steps via NINA #2 to confirm
   the second focuser (its own COM/USB port) is controllable independently.

**Record results** in §8 (RAM headroom, USB layout, any driver misbehavior) and in
`HARDWARE.md`. If step 4 or 5 fails, stop and we design a mitigation (separate USB
controllers, powered hub, or Alpaca-bridging one camera) before proceeding. If it
passes, the rest of Phase 0 is just software.

### 6.1 Phases

- **Phase 0 — Prove capture.** Stand up NINA #2; move guiding to the OAG; run the
  dumb OSC loop to its own folder; add `/api/system/stats` to watch load. Ingest
  via a second telescope-agent with a piggyback config. Verify two-camera
  USB/driver stability + RAM over a couple of nights.
- **Phase 1 — Rig-aware PhotonScript.** Thread `rig` through sub records,
  runs/QA/scoring, library layout, transfer. Runs page shows both.
- **Phase 2 — Calibration + processing per rig.** OSC flats/darks; OSC stacking.
- **Phase 3 — Planner / framing helper.** Recommend RC16 targets whose
  surroundings make good 600 mm wide-field companions; record piggyback rotation.
- **Phase 4 (optional) — Slew/flip gating** to reclaim lost subs, only if the
  measured loss rate justifies it.

## 7. Open risks / red-team targets

1. **Two-camera USB/driver stability** *(highest-risk unknown)* — does the OGMA
   ASCOM/native driver support two IMX571 cameras across two NINA instances at
   once? Shared USB3 controller bandwidth for two 26 MP streams?
2. **Scope-PC RAM/CPU** — two 26 MP pipelines + two agents + PHD2 + TheSky.
   Measure via the new stats endpoint before leaning on it.
3. **Disk + Starlink** — ~2× data volume; nightly disk fill; daytime transfer
   window contention. Per-rig retention policy?
4. **Mount coordinate access** — time-correlation (chosen) vs read-only Device
   Hub; verify TheSky allows a second read client if we want header RA/DEC.
5. **Slew/flip loss rate** — is "continuous & lossy" actually cheap? Measure the
   rejected-during-slew count on the piggyback in Phase 0.
6. **Pushover volume** — two NINA instances = two GroundStation senders. Route the
   piggyback's narration off (or tag it) so it folds into the new rate limiter
   rather than doubling alerts.
7. **PHD2 ownership** — confirm PHD2 uses GP678C (OAG) exclusively and the AP26CC
   is fully released to NINA #2.
8. **NINA multi-instance quirks** — profile isolation, port config, duplicated
   plate-solver setup, auto-update collisions.
9. **Piggyback focus** — AF cadence for OSC broadband; new focuser backlash /
   step size (fill `HARDWARE.md` §7).
10. **Target attribution at handoffs** — time-correlation edge cases when Rig A
    switches targets mid-night; make the boundary rule explicit.
